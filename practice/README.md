# Practice Track

This folder is your dedicated training area after you finish the chapter lessons and before you move to the challenge and interview sections.

## Learning flow

1. Study every chapter in the root folders.
2. Practice each topic here.
3. Re-run exercises until you can explain the logic without looking at the code.
4. Move to the real challenge folder.
5. Then move to the technical interview folder.

## Suggested structure

```text
practice/
├── README.md
├── 01-fundamentals/
├── 02-sorting/
├── 03-data-structures/
├── 04-trees-graphs/
├── 05-interview-drills/
└── tracker.md
```

## How to use it

- Pick one topic per day.
- Write the solution from memory.
- Test the code with Node.
- Write a short explanation of time complexity.
- Repeat until it feels easy.

## Goal

The goal is to build confidence before attempting the production-style challenges and technical interview questions.

## Example files by section

- 01-fundamentals: big-o.js, recursion.js, arrays.js, searching.js, fibonacci.js
- 02-sorting: insertion-sort.js, merge-sort.js, bubble-sort.js, quick-sort.js
- 03-data-structures: set.js, map.js, stack.js, queue.js, linked-list.js
- 04-trees-graphs: binary-tree.js, dfs.js, bfs.js
- 05-interview-drills: solve-one.js, explain.js

## Practice questions to ask yourself

- Can I explain this concept in plain English?
- What is the time complexity?
- What is the space complexity?
- What edge cases can break this?
- Can I solve it without looking at the original code?
- Can I explain the trade-offs and when to use it?

## Interview-style check

Before moving on, answer these:

1. What problem does this solve?
2. When would you use it?
3. What are the trade-offs?
4. What happens with edge cases?
5. Can you write it again from memory without hints?

## Rule before advancing

Only move to the next section when you can explain the concept, code it from memory, and answer the technical questions without looking.
